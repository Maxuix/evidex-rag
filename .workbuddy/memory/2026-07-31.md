## Markdown 语义切分碎片化排查

**问题**：Markdown 走 Semantic 切分链路时结果零碎，大段落被拆成单句；PDF 走同链路正常。

**根因**（已用诊断脚本 `tools/diagnose_md_chunking.py` 实证）：
1. Markdown 标题密集 → 每个标题触发 SECTION 硬边界（`semantic.py` `_boundary()` 的 `has_pending_titles`）；
2. `_select_all_regions()` 在每个硬边界处强制切割区域，`_select_region()` 对 ≤ max_chunk_tokens(800) 的小区域直接整体成 chunk，完全绕过 min_chunk_tokens(220)；
3. Markdown 的 mimetype 不在 `_SURFACE_BY_MIMETYPE`，surface_kind=logical 无 PAGE 边界，硬边界几乎全来自 SECTION。

**产出**：
- 排查报告：`Markdown语义切分碎片化排查报告.md`（项目根目录），含根因、Markdown vs PDF 对比、实证输出、方案 B（推荐）完整代码、方案 A（长期）说明。
- 诊断脚本：`tools/diagnose_md_chunking.py`，可复现碎片化并验证修复效果。

**推荐方案**：方案 B（小区域合并），仅改 `semantic_boundaries.py` 的 `_select_all_regions`，新增 `_merge_small_regions`，将 < min_chunk_tokens 的相邻区域合并（仅跨越 SECTION，不跨 PAGE/TABLE/BLOCK）。未实际改代码，待用户确认方案后实施。

**关键代码位置**：
- `src/rag_kb/document_processing/docling/semantic.py:257-281` `_boundary()`（根因一）
- `src/rag_kb/document_processing/semantic_boundaries.py:134-148` `_select_all_regions()`（根因二）
- `src/rag_kb/document_processing/semantic_boundaries.py:151-164` `_select_region()`（小区域 return [] 绕过最小约束）

## Chat 流式预览面板全 0 排查（已修正）

**现象**：web-test（诊断 UI）Chat 面板显示 `Attempt none / Delta events 0 / Reset events 0 / Gap invalid no / Last reset none`，文案"The authoritative terminal result replaced all preview content."。但 web-chat（用户 chat UI）stream 传输正常。

**已排除**：`preview_enabled` 不是根因——web-chat 能 stream 说明后端 broker/sink 已装配、preview delta 事件正常产生。后端 SSE endpoint（apps/api/routers/chat.py:248 stream_chat_run_events）对两前端一视同仁，下发 4-key `ChatAnswerPreviewEvent`（run_id/attempt/seq/delta），前端 hasExactKeys 校验能过。

**代码对比结论**：web-test 与 web-chat 的 `subscribeChatRun`/`parsePreviewDelta`/`applyPreviewDelta`/useEffect 依赖/`submitRun` 逻辑为同一份代码拷贝，无逻辑差异。

**根因（已确认）**：非 bug，是 web-test 的预期行为。web-test 初始化时 `readActiveRun`→`loadRun`（ChatView.tsx:211-230）恢复一个**已终态**的历史 run，主 useEffect（257-268）走 `if (!run || runIsTerminal)` 分支**不订阅 SSE**，直接 `terminalPreviewDiagnostics`（phase=replaced，计数保持初始 0）。web-chat 新发 run 非终态→订阅 SSE→收到 delta。用户已在 web-test 新发提问验证：`Delta events` 正常递增。后端 `_prepare_chat_sse_subscription`（chat.py:221-224）也在 run 终态时不建 preview 订阅，行为一致。

**关键代码位置**：
- apps/web-test/src/ChatView.tsx:211-230（初始化恢复 activeRun）、257-268（终态不订阅 SSE）、367（useEffect 依赖 `[client, knowledgeBase.id, loadMessages, run?.run_id, runIsTerminal]`）
- apps/api/routers/chat.py:192-240（_prepare_chat_sse_subscription，223 行终态时不建 preview 订阅）、248-303（stream_chat_run_events，265 行 ChatAnswerPreviewEvent）
